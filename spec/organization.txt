#    We defined the memory model and bindings which really had no dependencies.
#    Now the hard part.
#
#    All the of the product, sum, and group types, struct, enum, module, and
#    interface don't really need the idea of scopes or blocks, since their blocks
#    are not expression scopes or blocks.
#
#    The interface is a struct of function pointers so functions, methods,
#    lambdas, and structs have to be defined before interfaces.
#
#    A module is a group of static declarations, and functions. Their entry
#    points can be explained later.
#
#    An enum is probably the closest to a declaration.
#
#    All of functions, structs, enums, modules, interfaces, can be introduced
#    using the unmodified basic binding model since type modifier versions can be
#    joined in later.
#
#    Generics should be explained as an add on to functions, modules, and struct
#    after all of them have been defined.
#
#    Allocators ought to be declared after all of the above.
#    
#    When we are doing allocators we should know about error handling and about
#    how errors are enums passed through another effective data channel. In
#    assembly like going to a different instruction instead of the last one that
#    ran. We need to establish try and catch. Which are basically expressions so
#    we might want to do those first. And while we are at it the optional type
#    with orelse the .? operator and such might as well be introduced.
